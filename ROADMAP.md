# CheckAI — что доделать

Список задач по ролям, чтобы проект стабильно работал. Составлен по состоянию `main` на 09.10.2026 (после PR #6).
Приоритеты: **P0** — без этого проект работает с ошибками или не запускается у новичка, **P1** — нужно для нормальной работы, **P2** — улучшения.

Как запускать проект под каждую роль — в [TEAM_GUIDE.md](TEAM_GUIDE.md).

- [x] Ограничение частоты запросов на `/api/auth/login`, `/api/auth/register` и `/api/analyze` (перебор паролей, перегрузка OCR). `X-Forwarded-For` учитывается только при `TRUST_PROXY=1`.
- [x] Короче срок жизни токена (60 мин) + refresh-токен. Фронт обновляет токен сам; смена пароля завершает старые сессии.

**P2**

## Фича: бюджеты по категориям (неделя 16.10.2026)

Пользователь задаёт лимит на месяц: общий и/или по категориям. Лимиты повторяются каждый месяц.

**Фронтенд**
- [x] Раздел «Бюджеты»: выбор месяца, лимит / потрачено / осталось, полосы по категориям (80% — жёлтая, больше 100% — красная), прогноз до конца месяца и сколько можно тратить в день.
- [x] Форма лимитов с подсказкой «в среднем N ₸ в месяц» по прошлым чекам.
- [x] Предупреждение после сохранения чека, если он довёл лимит до 80% или превысил его; пометка «перерасход» в меню.
- [x] Пока на сервере нет `/api/budgets` (ответ 404/405), лимиты хранятся в `localStorage` и показывается плашка «только на этом устройстве».

**Бэкенд**
- [ ] Таблица `budgets`: `id`, `user_id` (FK, `ondelete=CASCADE`), `category` (`String(100)`, `NULL` — общий лимит), `limit` (`Float`, > 0), `created_at`, `updated_at`. Уникальность `(user_id, category)` — для `NULL` проверять в коде, т.к. SQLite считает `NULL` разными. Миграция Alembic `0003_budgets`, связь `User.budgets` с `cascade="all, delete-orphan"`.
- [ ] `GET /api/budgets` → `[{"category": "Кафе" | null, "limit": 15000.0}]`. Без лимитов — `[]`, не `404`.
- [ ] `PUT /api/budgets`, тело `{"budgets": [{"category", "limit"}]}` — заменяет весь список пользователя в одной транзакции, отвечает тем же форматом, что `GET`. Валидация: `limit > 0` и не больше 1e12, `category` обрезать по пробелам, пустая строка → `null`, повторы категорий — `422` с русским текстом, не больше 50 записей.
- [ ] Оба эндпоинта только с токеном (`401` без него), пользователь видит только свои лимиты. Удаление аккаунта удаляет лимиты.
- [ ] (P2) `GET /api/budgets/status?month=YYYY-MM` — потрачено по категориям за месяц на сервере, для Telegram-бота и уведомлений.

**ML**
- [ ] Бюджеты считаются по `category` позиций — ошибка категоризации сразу портит бюджет. Поднять приоритет задачи «Категоризация товаров моделью» из P1: категория из списка фронта (`Продукты, Одежда, Дом и быт, Транспорт, Кафе, Здоровье, Развлечения, Другое`) в ответе `/api/analyze` у каждой позиции.
- [ ] На эталонных чеках мерить точность категорий отдельной метрикой.

**QA**
- [ ] API: `GET` без лимитов → `[]`; `PUT` заменяет список целиком; `limit ≤ 0`, дубли категорий, 51 запись → `422`; без токена → `401`; пользователь B не видит лимиты A; удаление аккаунта удаляет лимиты.
- [ ] UI: 79% / 80% / 100% / 101% — цвет полосы и текст; предупреждение появляется только при переходе порога; прошлый месяц без прогноза; гость видит приглашение войти; смена аккаунта показывает лимиты нового; ширина 360 px; светлая тема.
- [ ] Режим без бэкенда: лимиты сохраняются в браузере и есть плашка; после выката API плашка пропадает.

**PM**
- [ ] Решить: переносить ли лимиты, заданные в браузере, на сервер после выката API (фронт может отправить их один раз).
- [ ] Порог предупреждения 80% — оставить или дать настроить.
- [ ] Тексты раздела и предупреждений, место бюджетов в демо/презентации.

## Зависимости между задачами

- Редактирование чека: бэк `PUT /api/receipts/{id}` → фронт форма редактирования → QA тесты.
- Профиль: бэк `PATCH/DELETE /api/auth/me` → фронт уже готов → QA проверяет.
- Качество распознавания: ML эталоны и скрипт оценки → QA прогон перед релизом → PM решает, достаточно ли.
- Категории: PM список → ML категоризация → бэк хранит → фронт показывает.
