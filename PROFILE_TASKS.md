## 0. Что теперь в профиле и откуда данные

| Блок | Что показывает | Откуда сейчас |
|---|---|---|
| Обложка | Имя (или часть email до `@`), email, «с нами с …», основная валюта | `GET /api/auth/me` |
| Цифры | Чеков, потрачено, средний чек, дней с нами | Считает фронт по **всем** чекам из `GET /api/receipts` |
| Активность | Тепловая карта за 26 недель, рекорд дней подряд, любимый день недели | Считает фронт по всем чекам |
| Привычки | Любимый магазин, топ-категория, самый крупный чек, этот месяц к прошлому | Считает фронт по всем чекам |
| Первые шаги | Имя, первый чек, лимит, правило категорий | `me`, чеки, `GET /api/budgets`, `GET /api/category-rules` |
| Личное | Имя, основная валюта | `PATCH /api/auth/me` |
| Вход и пароль | Email, новый пароль (с оценкой надёжности), текущий пароль | `PATCH /api/auth/me` |
| Аккаунты | Переключение между аккаунтами на устройстве | `localStorage` |
| Оформление | Тёмная / светлая / как в системе | `localStorage` |
| Данные | Счётчики и выгрузка JSON / CSV | Собирает фронт из загруженных данных |
| Удаление | Удаление аккаунта по паролю | `DELETE /api/auth/me` |

Контракт `PATCH` и `DELETE /api/auth/me` не менялся. Фронт теперь просто шлёт личные данные и данные входа двумя отдельными запросами.

## 1. Бэкенд

### 1.1. Сводка профиля одним запросом — **важно**

**Проблема.** Чтобы посчитать цифры, активность и привычки, фронт выкачивает всю историю пачками по 200 (`fetchAllReceipts` в `app.js`). На сотнях чеков это медленно и тяжело для телефона. Кроме того, логика «какая дата у чека» и «как пересчитать в основную валюту» живёт в двух местах.

**Предложение:** `GET /api/profile/stats` (или `GET /api/auth/me/stats`), все суммы — в основной валюте пользователя.

```json
{
  "base_currency": "KZT",
  "receipts_count": 148,
  "items_count": 1203,
  "total_spent": 1843200.0,
  "average_receipt": 12454.05,
  "converted": true,
  "unconverted": [{ "currency": "USD", "count": 2 }],
  "first_receipt_at": "2026-03-12",
  "last_receipt_at": "2026-11-03",
  "activity": [{ "date": "2026-11-03", "count": 2, "total": 8420.0 }],
  "top_store": { "name": "Magnum", "count": 31 },
  "top_category": { "id": 4, "total": 412000.0 },
  "biggest_receipt": { "id": 87, "total": 64300.0, "store": "Technodom" },
  "month_total": 152000.0,
  "prev_month_total": 171500.0
}
```

- `activity` — за последние 182 дня (26 недель), только дни, где были чеки.
- **Дата чека** — дата покупки (`receipts.date`), а если её нет — `created_at`. Так сейчас считает фронт (`receiptIso`), иначе цифры разойдутся.
- **Часовой пояс:** фронт группирует по местному дню пользователя. Предлагаем параметр `?tz=Asia/Almaty` (фронт передаст `Intl.DateTimeFormat().resolvedOptions().timeZone`).
- Пока эндпоинта нет, фронт продолжает считать сам. После его появления фронт перейдёт на него и перестанет качать всю историю ради профиля.

### 1.2. Аватар

**Проблема.** В `users` нет поля аватара, поэтому фронт показывает первую букву имени на градиенте.

**Предложение:**
- Поле `users.avatar_url` (nullable), которое отдаётся в `UserOut`.
- `POST /api/auth/me/avatar` (multipart, поле `file`): JPG/PNG/WEBP до 2 МБ. Сервер обрезает картинку до квадрата 256×256 и отвечает `UserOut`.
- `DELETE /api/auth/me/avatar` → `UserOut` с `avatar_url: null`.

Фронт готов добавить загрузку по клику на аватар, как только появится контракт.

### 1.3. «Выйти на всех устройствах»

**Сейчас.** Все токены пользователя отзываются только при смене пароля (`password_fingerprint` в `auth.py`). Отдельной кнопки «выйти везде» сделать нельзя, и список устройств тоже не показать.

**Предложение (минимум):** `users.token_version` (int) входит в токены. `POST /api/auth/logout-all` увеличивает версию и возвращает новую пару токенов для текущего устройства.
**По желанию:** `GET /api/auth/sessions` — устройство, IP, время последнего входа.

### 1.4. Полная выгрузка данных

**Проблема.** Фронт собирает JSON из того, что уже загрузил: чеки, категории, правила, лимиты. **Фото чеков в выгрузку не попадают** — в интерфейсе об этом есть пометка.

**Предложение:** `GET /api/auth/me/export` → ZIP с `data.json` (тот же состав, что выгружает фронт) и папкой `images/`. Полезно и для соответствия закону о персональных данных.

### 1.5. Смена основной валюты и курсы

**Проблема.** После `PATCH /api/auth/me` с новой `base_currency` курсы для старых чеков докачиваются в фоне (`rates.run_in_background`). Фронт сразу перезапрашивает чеки, и часть из них временно уходит в «не учтено — нет курса». Пользователь видит заниженную сумму и не понимает почему.

**Предложение:** в ответе `PATCH` добавить `"rates_pending": true`, пока фоновая задача не закончилась, и отдать возможность узнать статус (например, `GET /api/auth/me` с тем же флагом). Фронт тогда покажет «Пересчитываем по курсу…» и перезапросит данные сам.

### 1.6. Сброс пароля: письмо вместо токена в ответе

`POST /api/auth/forgot-password` отдаёт `reset_token` прямо в ответе — для продакшена нужно отправлять письмо со ссылкой. Договоримся о формате ссылки: предлагаем `/?reset=<token>`, фронт откроет форму нового пароля. UI на фронте пока не сделан, см. [раздел 3](#3-долги-фронтенда).

### 1.7. Мелочи (низкий приоритет)

- `UserOut` не отдаёт `updated_at` и `last_login_at`. Если будут, покажем «последний вход».
- Подтверждения email нет. Если появится, в обложке будет бейдж «email подтверждён».
- Тема хранится только в `localStorage`. Если нужна синхронизация между устройствами, нужно поле `users.preferences` (JSON) в `UserOut` и `PATCH /api/auth/me`.

## 2. ML

### 2.1. Источник категории не сохраняется

**Проблема.** ML отдаёт у позиции `category_source` (`rule` | `ai` | `keywords`), и фронт показывает его до сохранения чека. Но в `ItemOut` этого поля нет, и после сохранения источник теряется. Поэтому в профиле нельзя показать, например: «ИИ сам разложил 82% позиций, вы поправили 14».

**Нужно (ML + бэкенд):**
- Бэкенд сохраняет `category_source` в `receipt_items` при `POST /api/receipts/save` и отдаёт его в `ItemOut`.
- При ручном переносе (`POST /api/items/move`) источник становится `user`.
- ML: подтвердить, что `category_source` приходит у **каждой** позиции, в том числе в асинхронном пути (`/api/analyze/async`).

### 2.2. Нормализация названия магазина

**Проблема.** «Любимый магазин» группируется по точному названию (без учёта регистра и пробелов по краям). OCR пишет один и тот же магазин по-разному («MAGNUM», «Magnum Cash&Carry», «ТОО "Magnum"»), и статистика размазывается.

**Предложение:** ML возвращает рядом с `store` поле `merchant` — короткое каноническое имя сети без организационно-правовой формы и кавычек. Бэкенд его хранит, профиль и история группируют по нему.

### 2.3. Уверенность распознавания (по желанию)

Если ML может отдавать общую `confidence` по чеку (0–1), в профиле можно показать среднюю точность распознавания и подсветить в истории чеки, которые стоит проверить.

## 3. Долги фронтенда

Это делает фронтенд, от бэка и ML здесь ничего не нужно — список для полноты картины.

- Форма «Забыли пароль?» в окне входа и форма нового пароля по ссылке (эндпоинты уже есть, ждём решения по п. 1.6).
- Перейти на `GET /api/profile/stats`, когда он появится (п. 1.1).
- Загрузка аватара (п. 1.2), кнопка «Выйти на всех устройствах» (п. 1.3), выгрузка ZIP (п. 1.4).
