## 0. Общие договорённости (прочитать всем)

### Что сейчас не так

- Фронт подставляет `₸` ко всем суммам (`money()` в `app.js`, подписи «Цена, ₸», «Итог чека, ₸»).
- В базе у чека нет валюты. Чек на 50 $ сохранится и покажется как «50 ₸».
- Аналитика, категории и бюджеты складывают суммы всех чеков: 5 000 ₽ + 5 000 ₸ = «10 000 ₸».
- Regex-парсер всегда возвращает `'currency': '₸'`, Qwen валюту не определяет.

### Как будет

| Понятие | Что это | Где хранится |
|---|---|---|
| **Валюта чека** | В ней все суммы чека: итог, цены, суммы позиций. У позиций отдельной валюты нет | `receipts.currency`, код ISO 4217: `KZT`, `RUB`, `USD` |
| **Курс чека к тенге** | Сколько тенге стоит 1 единица валюты чека на дату покупки. Фиксируется при сохранении и больше не меняется | `receipts.rate_to_kzt`; для `KZT` всегда `1.0`; `null` — курс получить не удалось |
| **Основная валюта пользователя** | В ней итоги, аналитика, категории, бюджеты | `users.base_currency`, по умолчанию `KZT` |
| **Множитель к основной валюте** | На что умножить сумму чека, чтобы получить сумму в основной валюте. Считает сервер, фронт только умножает | поле `rate_to_base` в ответе API; `null` — пересчитать нельзя |

Правила:

1. **Карточка чека и строка в истории** — в валюте чека: «50,00 $».
2. **Сводки** (итоги истории, категории, анализ, бюджеты, профиль) — в основной валюте. Если в сводке есть пересчитанные чеки — перед суммой «≈».
3. **Чек без курса не складывается молча.** Он не входит в сводку, под ней строка: «Не учтено: 2 чека в USD — нет курса».
4. **Курсы** — официальные курсы Национального банка РК (все к тенге). Пересчёт между любыми двумя валютами — через тенге.
5. **Старые чеки** после миграции — `KZT`, курс `1.0`. Выглядят как сейчас.
6. **Совместимость**: пока сервер не отдаёт `currency`, фронт считает чек тенге. Каждый может работать, не дожидаясь остальных.

### Контракт API

Согласовать бэкенду и фронтенду в первый день. Если что-то меняете — сначала здесь, потом в коде.

**Новый эндпоинт** `GET /api/currencies` (без авторизации):
```json
[
  {"code": "KZT", "symbol": "₸", "name": "Казахстанский тенге", "digits": 0},
  {"code": "USD", "symbol": "$", "name": "Доллар США", "digits": 2}
]
```

**`POST /api/analyze`** — в `data` два новых поля:
```json
{"store": "…", "total": 52.5, "items": [], "currency": "USD", "currency_source": "symbol"}
```
`currency_source`: `"symbol"` — нашли символ или слово на чеке; `"country"` — валюту не нашли, определили по стране (БИН, ИНН…); `"default"` — ничего не нашли, подставили `KZT`.

**`POST /api/receipts/save`, `PUT /api/receipts/{id}`** — принимают `currency`. В `POST` по умолчанию `"KZT"`, в `PUT` без поля валюта чека не меняется. Неизвестная валюта → `422` «Валюта не поддерживается».

**Чек в ответах** (`/api/receipts`, `/api/receipts/{id}`, ответ сохранения):
```json
{
  "id": 42, "store": "Starbucks", "date": "2026-10-22", "total": 52.5,
  "currency": "USD", "rate_to_kzt": 486.2,
  "base_currency": "KZT", "rate_to_base": 486.2,
  "items": [{"name": "Latte", "quantity": 1, "price_per_unit": 5.25, "total_price": 5.25, "category": "Кафе"}]
}
```

**Пользователь** (`/api/auth/me`, ответы входа и регистрации): поле `base_currency`. `PATCH /api/auth/me` принимает `base_currency`.

**Аналитика и бюджеты** (`/api/analytics`, `/api/budgets/status`): все суммы в основной валюте, плюс
```json
{"base_currency": "KZT", "unconverted": [{"currency": "USD", "receipts": 2}]}
```
В `/api/analytics` ещё `converted_count` — сколько чеков вошло в суммы (`receipts_count` — все чеки).
Лимиты бюджетов (`/api/budgets`) — в основной валюте пользователя.

### Шаг 3. Курсы — `app/rates.py` (новый файл)

Источник — лента курсов Нацбанка РК на дату. Ожидаемый адрес: `https://nationalbank.kz/rss/get_rates.cfm?fdate=22.10.2026` (XML: элементы `item` с `title` — код валюты, `description` — курс, `quant` — за сколько единиц). **Первым делом откройте адрес в браузере и проверьте формат** — набросок ниже написан по памяти.

```python
NBK_URL = "https://nationalbank.kz/rss/get_rates.cfm?fdate={day:%d.%m.%Y}"

def _fetch_day(day: date) -> Dict[str, float]:
    """Все курсы на дату одним запросом: {"USD": 486.2, "RUB": 5.9, …} (тенге за 1 единицу)."""
    resp = httpx.get(NBK_URL.format(day=day), timeout=5)
    resp.raise_for_status()
    root = ElementTree.fromstring(resp.content)
    rates = {}
    for item in root.iter("item"):
        code, value, quant = item.findtext("title"), item.findtext("description"), item.findtext("quant") or "1"
        rates[code.strip()] = float(value) / float(quant)
    return rates
```

Публичные функции:

| Функция | Что делает |
|---|---|
| `ensure_rates(db, day)` | Если в `exchange_rates` нет **ни одной** строки за `day` — скачать всю ленту за этот день и сохранить **все** валюты из неё. Дата в будущем → сегодня. Пустой ответ (выходной, праздник) — пробовать предыдущий день, до 7 дней назад. Ошибка сети — записать в лог и вернуть без исключения |
| `rate_to_kzt(db, currency, day, fetch=True)` | `KZT` → `1.0` без запросов. Иначе — из таблицы, при `fetch=True` сначала `ensure_rates`. Нет курса → `None` |

Важно:
- **Ленту на дату скачиваем целиком и для чеков в тенге тоже.** Тогда, если пользователь сменит основную валюту на доллары, курсы на даты его чеков уже будут в базе, и при чтении в сеть ходить не нужно.
- **При чтении (`GET`) в сеть не ходим никогда**, только `fetch=False`. Запрос к Нацбанку — только при сохранении и редактировании чека.
- Тесты не должны ходить в интернет: подменяйте `rates._fetch_day` (`unittest.mock.patch`).

### Шаг 5. Множитель к основной валюте в ответах

В `ReceiptOut` добавить `currency: str = "KZT"`, `rate_to_kzt: Optional[float] = None`, `base_currency: str = "KZT"`, `rate_to_base: Optional[float] = None`.

Функция в `crud.py`, которую вызывают все эндпоинты, возвращающие чеки (`save_receipt`, `read_receipts`, `read_receipt`, `update_receipt`):

```python
def attach_base_rates(db, receipts, base: str):
    """Проставляет каждому чеку base_currency и rate_to_base (обычные атрибуты объекта, не колонки)."""
    for r in receipts:
        r.base_currency = base
        if r.rate_to_kzt is None:
            r.rate_to_base = None
        elif r.currency == base:
            r.rate_to_base = 1.0
        elif base == "KZT":
            r.rate_to_base = r.rate_to_kzt
        else:
            base_rate = rates.rate_to_kzt(db, base, receipt_day(r), fetch=False)
            r.rate_to_base = r.rate_to_kzt / base_rate if base_rate else None
    return receipts
```

`receipt_day(r)` — `r.date`, иначе дата из `r.created_at`. Курсы основной валюты читайте один раз на дату (словарь внутри функции), а не на каждый чек.

### Шаг 7. Аналитика и бюджеты

`get_analytics` и `get_budget_status` в [app/crud.py](app/crud.py) сейчас складывают суммы в SQL. Суммировать разные валюты в SQL нельзя, поэтому:
1. Выбрать чеки пользователя (за месяц — для бюджетов) вместе с позициями.
2. `attach_base_rates(db, receipts, user.base_currency)`.
3. Сложить в Python: итог чека × `rate_to_base`, суммы позиций × `rate_to_base` — по категориям, магазинам, месяцам.
4. Чеки с `rate_to_base = None` — не в суммы, а в `unconverted` (сгруппировать по валюте).
5. В ответ добавить `base_currency` и `unconverted` (`AnalyticsOut`, `BudgetStatusOut`).

Пользователю нужно передавать `current_user` целиком, а не только `user_id`, — для `base_currency`.

### Шаг 1. Определение валюты — `ml/app/currency.py` (новый файл)

```python
def detect_currency(lines: List[str]) -> Tuple[Optional[str], str]:
    """Валюта чека по OCR-строкам. Возвращает (код ISO или None, источник: 'symbol' | 'country' | 'default')."""
```

Порядок:
1. **Символы и слова** (источник `symbol`). Искать по всему тексту, считать совпадения, побеждает самая частая валюта:
   - `KZT`: `₸`, `тг`, `тнг`, `тенге`, `KZT`;
   - `RUB`: `₽`, `руб`, `р.` после числа, `RUB`, `RUR`;
   - `USD`: `$`, `USD`; `EUR`: `€`, `EUR`;
   - `KGS`: `сом`, `KGS`; `UZS`: `сум`, `сўм`, `UZS`;
   - `CNY`: `¥`, `元`, `CNY`, `RMB`; `TRY`: `₺`, `TL`, `TRY`.

   Осторожно с ложными совпадениями: `р.` в «р/с», «р-н», `сом` внутри слов, `$` от OCR-мусора. Проверяйте границы слова и соседство с числом.
2. **Страна** (источник `country`), если символов нет:
   - Казахстан → `KZT`: `БИН`, `ИИН`, `РНМ`, `ЗНМ`, «НДС 12%», «ҚҚС», казахские буквы `ә ғ қ ң ө ұ ү һ і`;
   - Россия → `RUB`: `ИНН` (10 или 12 цифр), `ФН`, `ФД`, `ФП`, «НДС 20%», `ОФД`, «Кассовый чек».
3. Ничего не нашли → `(None, "default")`. Сервер подставит `KZT`.

Возвращайте только коды из списка валют (раздел 0). Найденную валюту не из списка — `None`.

Подключение — одно место для обоих парсеров: в `analyze_receipt` ([app/ocr.py](app/ocr.py), строка ~125) после выбора парсера:
```python
currency, source = detect_currency(lines)
parsed["currency"], parsed["currency_source"] = currency or "KZT", source
```
Это файл бэкенда — согласуйте, кто вносит.

### Шаг 2. Числа в разных форматах — `clean_number` в `app/parser.py`

Сейчас все запятые становятся точками: `clean_number("1,234")` → `1.234` вместо `1234`. В долларовых и евро-чеках суммы будут в 1000 раз меньше.

Новые правила:
- есть и `.`, и `,` → десятичный разделитель — тот, что **правее**, второй — разделитель тысяч: `1,234.50` → `1234.5`, `1.234,50` → `1234.5`;
- только `,` и после неё ровно 3 цифры (`1,234`, `12,500`) → разделитель тысяч, **если** валюта чека `USD`/`EUR`/`CNY` (передать валюту параметром или определить заранее); иначе — десятичный, как сейчас (`0,450` кг);
- пробелы внутри числа (`1 234,50`) — убирать, как сейчас.

Обязательные проверки (вынести в тест):

| Вход | Валюта | Ожидается |
|---|---|---|
| `1 234,50` | KZT | 1234.5 |
| `1234.50` | KZT | 1234.5 |
| `0,450` | KZT | 0.45 |
| `1,234.50` | USD | 1234.5 |
| `1,234` | USD | 1234 |
| `12.50` | USD | 12.5 |
| `1.234,50` | EUR | 1234.5 |
| `65900.00` | RUB | 65900 |

Ту же правку — в `ml/app/parser.py` (копия). И проверить, как числа разбирает `agent_parser.py` (`_parse_number`).
