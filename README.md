# CheckAI — Интеллектуальный анализ кассовых чеков

Автономный сервис на базе искусственного интеллекта для автоматического извлечения товаров, цен, количества, реквизитов организации и итоговой суммы из фотографий кассовых чеков.

## Описание проекта

Обработка бумажных и электронных кассовых чеков вручную требует значительных временных затрат и подвержена человеческим ошибкам. **CheckAI** автоматизирует этот процесс:

1. Выполняет оптическое распознавание текста (OCR) с использованием нейросети PaddleOCR.
2. Передаёт распознанный текст языковой модели Qwen 2.5, которая интеллектуально извлекает товары, цены и реквизиты.
3. Фильтрует служебную информацию (адреса, реквизиты терминала, НДС, ФН/ФД/ФП).
4. Предоставляет результат через интерактивный веб-интерфейс с возможностью сохранения в базу данных.

---

## Ключевые возможности

- **Автономность и безопасность**: Распознавание выполняется полностью локально, без отправки данных во внешние облачные API.
- **ИИ-парсинг**: Языковая модель Qwen 2.5 анализирует текст чека, корректируя ошибки OCR и структурируя данные.
- **Мультивалютность и курсы Нацбанка РК**: Поддержка нескольких валют (`KZT`, `RUB`, `USD`, `EUR`, `KGS`, `UZS`, `CNY`, `TRY`) с официальным пересчётом курсов на дату покупки, аналитикой в основной валюте пользователя и прозрачным учётом чеков без курса.
- **Docker-контейнеризация**: Весь проект запускается одной командой, без необходимости устанавливать Python, библиотеки или модели вручную.
- **История чеков**: Сохранение распознанных чеков в базу данных SQLite с возможностью просмотра и аналитики.
- **Аккаунты**: Регистрация и вход по JWT, несколько аккаунтов на одном устройстве с быстрым переключением, профиль пользователя.
- **Подробности покупки**: Карточка чека со всеми позициями, категориями, фото и проверкой суммы.
- **Экспорт данных**: Скачивание результата в формате `.json`.

## Установка и запуск

Полная версия проекта (сайт, бэкенд, ML) — в ветке `main`. Перед запуском обновите её:

```powershell
git checkout main
git pull
```

Два способа запуска: **Docker** (ничего не нужно ставить, кроме Docker Desktop) и **без Docker** (быстрее для разработки).

### Кому какой режим

| Роль | Команда | Что поднимается | RAM |
|---|---|---|---|
| Бэкенд, фронтенд | `uvicorn server:app --reload` или `docker compose up -d` | Только сайт и API. Чеки распознаются запасным парсером `app/parser.py`, Ollama не нужна | ~0,5 ГБ |
| ML | `docker compose --profile full up -d` или без Docker с установленной Ollama | Сайт + Ollama (Qwen 2.5:3b) | ~4–5 ГБ |
| QA, демонстрация | `docker compose --profile full up -d --build` | Всё, как у пользователя | ~4–5 ГБ |

Без Ollama сайт, аккаунты, история и валюты работают, а распознавание чека переключается на запасной парсер (точность ниже).

### Подготовка (один раз)

Создайте файл `.env` с ключом для подписи токенов:

```powershell
copy .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Вставьте полученную строку в `.env` после `SECRET_KEY=`.

### Способ А. Docker

Нужен запущенный [Docker Desktop](https://www.docker.com/products/docker-desktop/). Ollama отдельно ставить не нужно.

```powershell
docker compose --profile full up -d --build
# Первый раз: скачать языковую модель (~2 ГБ)
docker compose exec ollama ollama pull qwen2.5:3b
```

Откройте `http://localhost:8000`. Остановить — `docker compose --profile full down`.

- Без `--profile full` Ollama не запускается — поднимается только сайт.
- Папка `ml/` попадает в образ только при сборке: после `git pull` запускайте с `--build`. Папки `app/` и `frontend/` подключены к контейнеру напрямую — правки видны после перезапуска или `F5`.

### Способ Б. Без Docker

Нужен Python 3.11+.

**Один раз:** установите [Ollama](https://ollama.com/download/windows) (в PowerShell — `irm https://ollama.com/install.ps1 | iex`), откройте новый терминал и скачайте модель; затем подготовьте окружение:

```powershell
ollama pull qwen2.5:3b

python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

**Каждый раз:**

```powershell
.venv\Scripts\activate
uvicorn server:app --host 127.0.0.1 --port 8000 --reload
```

Откройте `http://localhost:8000`, Swagger — `http://localhost:8000/docs`. Остановить — `Ctrl+C`. Ollama на Windows работает в фоне (значок в трее); если её нет — запустите из меню «Пуск».

После `git pull` выполните `pip install -r requirements.txt`, если менялись зависимости.

### Проверка, что всё работает

1. `http://localhost:8000/api/health` — должно быть `"status": "healthy"`. Без Docker поле `ollama` пока показывает `unavailable`, даже когда Ollama работает: проверка обращается к адресу контейнера.
2. Загрузите фото чека. Первый чек обрабатывается дольше (до минуты) — загружаются модели.
3. В логе сервера не должно быть строки «Ollama/LLM недоступна… Используется встроенный парсер». Если она есть — Ollama не запущена или не скачана модель.

### Частые проблемы

| Проблема | Решение |
|---|---|
| Команда `ollama` не найдена | Откройте новое окно терминала |
| `Set SECRET_KEY in .env` при запуске Docker | Заполните `SECRET_KEY` в `.env` |
| Распознавание слабое, позиции не находятся | Qwen не используется — см. пункт 3 проверки |
| После `git pull` в Docker старое поведение | Запустите с `--build` |
| Порт 8000 занят | Укажите другой: `--port 8001` |
| Тесты пишут в рабочую базу | Перед тестами: `$env:DATABASE_URL="sqlite:///data/test.db"` (подробнее — BACKEND_GUIDE, раздел «Тесты») |

## Веб-интерфейс

Интерфейс — HTML + CSS + JS без сборки: разметка в [`frontend/templates/index.html`](frontend/templates/index.html), стили в [`frontend/static/css/app.css`](frontend/static/css/app.css), логика в [`frontend/static/js/app.js`](frontend/static/js/app.js) (сервер отдаёт их по адресу `/static/...`). Все данные он получает через REST API; к базе напрямую не обращается.

### Разделы

| Раздел | Что делает |
|---|---|
| **Добавить чек** | Загрузка фото или съёмка камерой телефона (или демо-чек), распознавание с показом этапов, правка распознанного чека, сохранение в историю, скачивание JSON |
| **История и расходы** | Список чеков за период, поиск по магазину и товару, сумма, средний чек, экспорт в CSV. Клик по чеку открывает подробности |
| **Категории** | Расходы по категориям товаров |
| **Анализ расходов** | График по дням/месяцам и разбивка по категориям |
| **Профиль** | Данные аккаунта, аккаунты на устройстве, редактирование и удаление аккаунта (виден только после входа) |

### Аккаунты

- **Гостевой режим.** Распознавать чеки можно без входа. При нажатии «Сохранить в историю» открывается окно входа; после входа чек сохраняется автоматически.
- **Вход и регистрация** — кнопка «Войти / Регистрация» в шапке. Access-токен (живёт час) хранится в `localStorage` (`checkai_token`) и отправляется в заголовке `Authorization: Bearer <токен>`, refresh-токен (30 дней) — в `checkai_refresh`. Если access-токен истёк (ответ `401`), интерфейс один раз обновляет пару через `POST /api/auth/refresh` и повторяет запрос; если не получилось (refresh истёк или пароль сменили), переходит в гостевой режим.
- **Меню аккаунта** — клик по аватару в шапке: «Профиль и настройки», список других аккаунтов, «Добавить аккаунт», «Выйти».
- **Смена аккаунта.** Каждый аккаунт, в который входили на этом устройстве, запоминается (до 5 штук, `localStorage` → `checkai_accounts`). Переключение — в меню аккаунта или в профиле, без повторного ввода пароля. Если сохранённая сессия истекла, откроется вход с подставленным email. Крестик в профиле убирает аккаунт с устройства.
- **Выход** удаляет текущий аккаунт из списка сохранённых на устройстве.
- **Редактирование аккаунта** (Профиль): имя, email, новый пароль. Для смены email или пароля нужен текущий пароль.
- **Удаление аккаунта** (Профиль): требует пароль и подтверждение; удаляет аккаунт и все его чеки.

- **Смена пароля** завершает все остальные сессии этого аккаунта: старые токены перестают действовать, текущая вкладка получает новые.

### Подробности покупки

Клик (или `Enter`) по чеку в истории открывает карточку: магазин, дата и время покупки, итог, категория, дата сохранения, фото чека (если сервер вернул `image_path`), все позиции с количеством, ценой и категорией. Если сумма позиций расходится с итогом чека больше чем на 1 ₸, показывается предупреждение — это признак ошибки распознавания. Из карточки можно скачать чек в JSON или удалить его.

Кнопка «Редактировать» в карточке открывает ту же форму, что и после распознавания. Сохранение отправляет `PUT /api/receipts/{id}` (тело как у `POST /api/receipts/save`).

### Добавление чека

- Файл проверяется до отправки: JPG, PNG, WEBP, BMP или TIFF, не больше 10 МБ (как `MAX_UPLOAD_MB` на сервере). Для HEIC с iPhone показывается подсказка, как сохранить фото в JPG.
- Во время распознавания видны этапы «Загрузка → Распознавание текста → Анализ» и прошедшее время, кнопки заблокированы. Прогресс загрузки — настоящий; переход к «Анализу» сервер не сообщает, он показывается примерно через 5 секунд после загрузки.
- Распознанный чек сразу открывается в форме: магазин, дата, время, позиции (название, количество, цена, сумма, категория), итог. Сумма строки пересчитывается при смене количества или цены; если сумма позиций не совпадает с итогом, можно одной кнопкой сделать её итогом.
- Категории позиций предлагаются по названию товара и сохраняются на сервере; у старых чеков без категории она угадывается по названию.

### Прочее

- **Экспорт CSV** — выгружает чеки, видимые в истории с учётом периода и поиска, по строке на позицию. Разделитель `;` и запятая в дробях — файл открывается в Excel без настройки.
- **Тема** — кнопка ☀/☾ в шапке. По умолчанию берётся тема системы, выбор запоминается (`localStorage` → `checkai_theme`).
- **История** загружается с сервера порциями по 200 чеков и показывается по 20 с кнопкой «Показать ещё».

## Спецификация API

Запросы, помеченные 🔒, требуют заголовок `Authorization: Bearer <access_token>`. Интерактивная документация — `http://localhost:8000/docs`.

### Справочник валют

- **URL**: `GET /api/currencies` (без авторизации)
- **Ответ**: Список поддерживаемых валют:
  ```json
  [
    {"code": "KZT", "symbol": "₸", "name": "Казахстанский тенге", "digits": 0},
    {"code": "USD", "symbol": "$", "name": "Доллар США", "digits": 2}
  ]
  ```

### Регистрация и вход

- **URL**: `POST /api/auth/register` — тело `{"email", "password", "full_name"?}`
- **URL**: `POST /api/auth/login` — тело `{"email", "password"}`
- **Ответ**: `{"access_token", "refresh_token", "token_type": "bearer", "user": {"id", "email", "full_name", "base_currency": "KZT", "created_at"}}`
- **Ошибки**: `400` с `{"detail": "..."}`, `422` — ошибки валидации, `429` — больше 10 попыток в минуту с одного IP
- **URL**: `POST /api/auth/refresh` — тело `{"refresh_token"}`, ответ как у входа (новая пара токенов). `401`, если refresh-токен истёк, подделан или пароль с тех пор сменили.

Access-токен живёт 60 минут, refresh-токен — 30 дней. В оба токена записан отпечаток пароля: после смены пароля все выданные раньше токены перестают действовать.

### Аккаунт пользователя

- 🔒 `GET /api/auth/me` — текущий пользователь (содержит `base_currency`, по умолчанию `"KZT"`).
- 🔒 `PATCH /api/auth/me` — смена данных. Тело (все поля необязательны):
  ```json
  { "full_name": "Новое имя", "email": "new@example.com", "new_password": "...", "current_password": "...", "base_currency": "USD" }
  ```
  `current_password` обязателен при смене `email` или `new_password`. Для смены имени или `base_currency` пароль не требуется. Ответ — как у входа: новая пара токенов и пользователь. Ошибки — `400` с `detail` (неверный текущий пароль, email занят), `422` при неподдерживаемой валюте.
- 🔒 `DELETE /api/auth/me` — удаление аккаунта. Тело `{"password": "..."}`. Удаляет пользователя, все его чеки и их фото, ответ `{"success": true}`. Неверный пароль — `400`.

### Анализ чека

- **URL**: `POST /api/analyze`
- **Тип**: `multipart/form-data`
- **Параметр**: `file` — изображение чека (JPEG, PNG, WebP, BMP, TIFF), до `MAX_UPLOAD_MB` (10 МБ)
- **Ответ**: `{"success": true, "data": {..., "currency": "KZT", "currency_source": "symbol"}}`. Источник: `"symbol"` (символ/слово валюты на чеке), `"country"` (по реквизитам страны), `"default"` (подставлен `KZT`).
- **Категории позиций**: у каждой позиции `category_id`, `category` (название) и `category_source` — `"rule"` (правило пользователя, важнее ИИ), `"ai"` (Qwen), `"keywords"` (ключевые слова) или `null` (не определена). Токен необязателен: с ним раскладка идёт по категориям и правилам пользователя, у гостя — по стандартным категориям, и `category_id` всегда `null`.
- **Ограничение**: 15 запросов в минуту с одного IP

### Сохранение чека в БД

- 🔒 **URL**: `POST /api/receipts/save`
- **Тип**: `application/json`
- **Тело**: JSON с данными чека (`store`, `date`, `time`, `total`, `currency` (по умолчанию `"KZT"`), `image_path`, `items[]`). Неизвестная валюта -> `422`.
- **Категория позиции**: `category_id` (чужой или несуществующий -> `422` «Категория не найдена»); без него — `category` (название, без учёта регистра; категории с таким названием нет — `null`, новая не создаётся).
- **Категория чека** вычисляется сервером: категория самой дорогой позиции, при равенстве — первой из них. `category_id` чека учитывается, только если позиций нет.
- **Ответ**: Сохранённый чек с полями `category_id`, `category`, `currency`, `rate_to_kzt` (официальный курс НБ РК на дату чека), `base_currency`, `rate_to_base` (множитель к основной валюте пользователя; `null`, если курс недоступен). У позиций есть `id`, `category_id` и `category`.

### Получение истории чеков

- 🔒 **URL**: `GET /api/receipts?skip=0&limit=100` (`limit` до 500)
- **Фильтры** (необязательны): `from` и `to` — даты покупки `ГГГГ-ММ-ДД` включительно; `category_id` — чеки, где есть позиция этой категории (у чека без позиций — его собственная), `0` — «Без категории»; `q` — поиск по магазину и названиям товаров без учёта регистра
- **Ответ**: Список чеков пользователя (новые по дате покупки первыми) вместе с позициями, `currency`, `base_currency`, `rate_to_base`

### Один чек и редактирование

- 🔒 `GET /api/receipts/{id}` — один чек с позициями (`404`, если его нет или он чужой)
- 🔒 `PUT /api/receipts/{id}` — заменить данные чека (принимает `currency`; без него валюта чека не меняется); курс берётся заново при смене даты или валюты, а также если раньше его получить не удалось. Позиции заменяются целиком и **получают новые `id`** — после редактирования перечитайте чеки

### Аналитика

- 🔒 **URL**: `GET /api/analytics`
- **Ответ**: Сводная статистика по чекам в основной валюте пользователя (`base_currency`), а также `unconverted: [{"currency": "USD", "receipts": 2}]` (чеки, для которых нет курса, не входят в общие суммы). `receipts_count` — все чеки, `converted_count` — вошедшие в суммы; `avg_receipt` считается по учтённым. `by_category` — словарь «название → сумма», позиции без категории — под ключом `"Без категории"`

### Категории

Категории у каждого пользователя свои: при регистрации создаются 8 стандартных (Продукты, Одежда, Дом и быт, Транспорт, Кафе, Здоровье, Развлечения, Другое), дальше их можно переименовывать, удалять и добавлять свои. «Без категории» — это `category_id: null`, а не категория. По описанию категории ИИ раскладывает товары.

Объект категории: `{"id": 12, "name": "Косметика", "description": "Крем, шампунь, тушь, помада", "icon": "💄", "position": 8}`.

| Метод и путь | | Тело | Ответ |
|---|---|---|---|
| `GET /api/categories` | 🔒 | — | Категории по `position` |
| `GET /api/categories/defaults` | | — | `[{"name", "description", "icon"}]` — стандартные, для гостя |
| `POST /api/categories` | 🔒 | `{"name", "description"?, "icon"?}` | `201`, категория в конце списка |
| `PATCH /api/categories/{id}` | 🔒 | любые из `name`, `description`, `icon` | Категория |
| `DELETE /api/categories/{id}?move_to={id}` | 🔒 | — | `{"success": true, "moved_items": 14, "deleted_budget": true}` |
| `PUT /api/categories/order` | 🔒 | `{"ids": [3, 1, 12, …]}` — все id пользователя, каждый один раз | Категории в новом порядке |
| `POST /api/items/move` | 🔒 | `{"item_ids": [101, 102], "category_id": 12, "remember": true}` | `{"moved": 2, "rules_created": 1}` |
| `GET /api/category-rules` | 🔒 | — | `[{"id", "pattern", "category_id", "category", "created_at"}]` |
| `DELETE /api/category-rules/{id}` | 🔒 | — | `{"success": true}` |

- **Ограничения**: `name` — 1–50 символов после обрезки пробелов, уникально без учёта регистра (`409` «Категория «Косметика» уже есть»), нельзя «Без категории» (`422`); `description` — до 300 символов, пустое -> `null`; `icon` — до 8 символов, пустое -> `◌`; не больше 50 категорий (`422`). Создание — не больше 30 в минуту с одного IP.
- **Удаление**: с `move_to` позиции, чеки и правила переходят в эту категорию; без него позиции и чеки остаются без категории, а правила удаляются. Лимит бюджета удаляемой категории удаляется в любом случае. `move_to` — та же или чужая категория -> `422`. Чужая категория в пути -> `404`.
- **Перенос позиций**: `category_id: null` — «Без категории». Хотя бы одна позиция чужая -> `404`, не переносится ни одна. `remember: true` — запомнить правило «название товара → категория» (название нормализуется: «Крем NIVEA 50мл» и «Крем Nivea 100 мл» -> `крем nivea`); при `category_id: null` правило не создаётся. `rules_created` — сколько правил создано или перенаправлено в другую категорию. Категории затронутых чеков пересчитываются.

### Удаление чека

- 🔒 **URL**: `DELETE /api/receipts/{id}`

### Бюджеты и лимиты расходов

- 🔒 **URL**: `GET /api/budgets`
  - **Ответ**: Список установленных лимитов текущего пользователя (общий лимит первым, затем в порядке категорий):
    ```json
    [
      {"category_id": null, "category": null, "limit": 150000.0},
      {"category_id": 12, "category": "Кафе", "limit": 15000.0}
    ]
    ```
    Если лимиты не заданы, возвращается `[]` со статусом `200` (а не `404`).
- 🔒 **URL**: `PUT /api/budgets`
  - **Тело**: `{"budgets": [{"category_id": 12, "limit": 15000.0}, {"category_id": null, "limit": 150000.0}]}`. `category_id: null` — общий лимит.
  - **Поведение**: Полная замена всех лимитов пользователя в одной транзакции. Ответ в том же формате, что у `GET /api/budgets`.
  - **Валидация (`422`)**:
    - `limit > 0` и `limit <= 1e12` (до 1 триллиона);
    - Старый формат с `category` (название) не принимается;
    - Чужой или несуществующий `category_id` — «Категория не найдена»;
    - Запрещены дубликаты категорий (в том числе повторный `null`);
    - Не более 50 лимитов на одного пользователя;
    - Тексты ошибок валидации отдаются на русском языке.
- 🔒 **URL**: `GET /api/budgets/status?month=YYYY-MM`
  - **Параметры**: `month` (необязательно, формат `ГГГГ-ММ`, по умолчанию — текущий месяц по UTC).
  - **Ответ**: Фактический расчёт расходов за месяц по каждому лимиту:
    ```json
    {
      "month": "2026-10",
      "total_budget": 150000.0,
      "total_spent": 45000.0,
      "budgets": [
        {
          "category_id": null,
          "category": null,
          "limit": 150000.0,
          "spent": 45000.0,
          "remaining": 105000.0,
          "percent": 30.0,
          "percentage": 30.0,
          "is_over_budget": false
        },
        {
          "category_id": 12,
          "category": "Кафе",
          "limit": 15000.0,
          "spent": 16200.0,
          "remaining": -1200.0,
          "percent": 108.0,
          "percentage": 108.0,
          "is_over_budget": true
        }
      ]
    }
    ```
