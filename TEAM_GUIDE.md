# Руководство для команды разработки CheckAI

В проекте реализована гибкая гибридная архитектура. Каждый участник команды может запускать проект в том режиме, который нужен именно для его задач, не перегружая компьютер лишними сервисами.

---

## 1. Бэкенд-разработчик (Backend)

Как бэкендеру, вам **не нужна** тяжёлая модель Ollama для разработки API, бизнес-логики, схем и базы данных. 

### Вариант А: Запуск в Docker (легковесный режим)
Запуск только веб-сервера (без Ollama):
```bash
docker compose up
```
* Поднимется только контейнер `web` на порту `8000`.
* Потребляет минимум RAM и не нагружает GPU/CPU.
* Распознавание чеков работает через встроенный быстрый алгоритмический парсер (`app/parser.py`).

### Вариант Б: Запуск напрямую без Docker (самый быстрый для разработки)
```bash
# 1. Активировать виртуальное окружение
.\.venv\Scripts\Activate.ps1    # Windows (или source .venv/bin/activate в Linux/macOS)

# 2. Запустить сервер с авто-перезагрузкой при изменении кода
python -m uvicorn server:app --reload
```
* Сервер стартует за 0.5 секунды.
* Любое изменение в коде сразу перезапускает приложение.
* Интерактивная документация Swagger: `http://localhost:8000/docs`.
* База данных SQLite лежит в `data/checkai.db`. Миграции Alembic применяются автоматически при старте.

## 2. Фронтенд-разработчик (Frontend)

Фронтендер работает со статикой и JS без сборщиков (Vanilla HTML/CSS/JS в `frontend/templates/index.html`).

### Запуск окружения:
```bash
docker compose up
```
или локально:
```bash
python -m uvicorn server:app --reload
```
### Особенности работы:
1. Папка `frontend/` смонтирована в контейнер «на лету» (`volumes`). Это значит, что любые правки в `frontend/templates/index.html` сразу видны в браузере после нажатия `F5` — **пересобирать контейнер не нужно**.
2. Распознавание чеков работает быстро (Ollama не требуется).
3. Все запросы интерфейса идут к API по адресам `/api/*` (авторизация через JWT в `localStorage`).

## 3. ML / AI Инженер (Machine Learning)

ML-специалист работает с предобученной моделью Qwen и промптами агента в папке `ml/`.

### Запуск полного стека (с контейнером Ollama):
```bash
# Запуск веб-сервера + Ollama
docker compose --profile full up -d

# Первый раз: скачать языковую модель Qwen внутрь Ollama
docker compose exec ollama ollama pull qwen2.5:3b
```
### Особенности работы:
1. `app/ocr.py` автоматически обнаруживает работающую Ollama и направляет распознанный OCR-текст в модуль `ml/app/agent_parser.py`.
2. Логи работы нейросети можно смотреть командой:
   ```bash
   docker compose logs ollama -f
   ```
3. Тестирование промптов и парсера изолированно:
   ```bash
   python ml/test_ocr.py
   ```

## 4. Тестировщик / QA

Тестировщику важно проверять систему как в легковесном, так и в полнофункциональном режиме.

### Сценарий 1: Регрессионное и функциональное тестирование (UI, API, БД)
```bash
docker compose up -d
```
* Проверка регистрации, входа, выпуска JWT-токенов.
* Проверка загрузки чека и корректности сохранения в SQLite.
* Проверка удаления чека и прав доступа (анонимы не должны иметь доступа к чужим чекам).
* Проверка Swagger API: `http://localhost:8000/docs`.

### Сценарий 2: Комплексное E2E-тестирование с ИИ (LLM Integration)
```bash
docker compose --profile full up -d
```
* Проверка качества распознавания сложных чеков с помощью языковой модели.
* Проверка самокоррекции итоговой суммы чека в модуле `agent_parser.py`.

### Остановка и очистка тестового стенда:
```bash
# Остановить контейнеры
docker compose --profile full down

# Полная очистка с удалением тестовых данных
docker compose --profile full down -v
```
